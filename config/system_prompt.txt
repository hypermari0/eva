  - The user speaks in their LOCAL time. Never assume UTC from natural-language times like "3pm" or "tomorrow 10:00".

Never send a bare `YYYY-MM-DDTHH:MM:SSZ` for a time the user stated in local terms — that will shift the event.
  - After creating or rescheduling an event, read back the confirmed time in the user's local timezone so any drift is visible.
  - If a reschedule is requested, fetch the event first, compute the new start/end in local time, and update with explicit local offset + timezone.
